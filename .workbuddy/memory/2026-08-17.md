## WorkBuddy 沙箱关键坑（可复用）

- **`rm` 是安全删除 shim**：`rm` 是 shell 函数，调用 `${CODEBUDDY_SAFE_DELETE_BIN_DIR}/rm`（genie-trash + powershell 回收站兜底），**失败即 fail-closed**（trash 失败则中止，不真正删除）。BASH_ENV 指向 `safe-delete-bash-env.sh`，且导出为 `BASH_FUNC_rm%%` 环境变量，子 shell 也会继承。
  - 绕过（仅用于合法重建生成目录）：`env -u BASH_ENV bash -c 'rm() { /usr/bin/rm "$@"; }; export -f rm; env -u BASH_ENV bash scripts/xxx.sh'`。注意必须用绝对路径 `/usr/bin/rm`（用 `command rm` 仍会命中 shim 二进制，因为 PATH 里 shim 目录在前）。
- **`uv` 在 Windows Git Bash 下不能解析 MSYS 路径**（`/d/yecll/...` 被 Rust 错拼成 `D:\d\yecll\...`）：对 `--directory` 等参数用 `cygpath -w` 转原生 Windows 路径；非 Windows 无 cygpath 时保留原样。
- `generate-goose-config.py` 自定位（`Path(__file__).resolve()`），但被脚本以 MSYS 路径传给原生 python3 会失败——同样需 cygpath。
- `source_image` 字段是死元数据：模型里定义、update 时原样保留，但 **web 模板从不渲染/服务该图**，故 283 条 vocab JSON 里的旧绝对/相对路径属非功能性遗留，可不处理（或按需机械改写）。
